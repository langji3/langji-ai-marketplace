# 独立 code-simplifier 插件 Spec

## 背景与目标

现有 `ai-dev-protocol` 负责开发流程；代码实现仍可能因假想需求、冗余抽象和未核实的数据关系而变得难以连续阅读。新增可单独安装和维护的 `code-simplifier` 插件，只有一个公开 skill，帮助编写、修改或审查代码时选择必要的结构，并保持已有行为。

- Marketplace 隔离分支：`codex/20260929-langji-code-simplifier`；工作目录：`C:\Users\14550\.codex\worktrees\code-simplifier\langji-ai-marketplace`。独立源码目录：`D:\Project\personal\code-simplifier`，与 `D:\Project\personal\ai-dev-protocol` 同级。
- 合并、推送、发布和更改已安装的个人插件配置均不在本次授权内。

## 本次范围

1. 在独立源码目录建立可持续维护的插件，其唯一公开 skill 是 `skills/code-simplifier/SKILL.md`；经验证的版本再以 `plugins/code-simplifier/` 快照进入 marketplace。保持正常自动发现。描述应让 AI 在执行代码审查（即使用户只说“审查代码”）时发现并加载它，同时聚焦简洁性和可读性，不吸引无关任务。
2. 通用原则服从目标项目既有风格，以 Java/Spring 业务层为例：先核实实现、调用方和真实数据关系；避免假想分支、配置、服务、工具类或查询；短小、单次使用、无独立业务意义的连续逻辑优先留在主流程。抽取须有具体收益，例如复用、复杂逻辑隔离、事务或权限边界；不追求方法数或行数最少，也不合并为巨型方法。
3. 编写、修改代码时在已授权范围内应用这些原则；用户要求优化、简化或审查时检查指定范围。审查只报告有证据的问题，技能的自动选中不扩大修改授权。
4. 简化须保持请求、返回、异常、权限、事务和副作用。固定选项适合时可使用有序不可变常量，不将其推广为所有数据的静态缓存规则。删除“全部”等产品能力属于需求变化，交由项目现有流程决定。
5. 独立源码目录维护版本、许可、验证与可重复更新说明；按 marketplace 现有组织方式登记 Codex、Claude 与目录入口，并记录来源版本与快照校验。注明上游来源、Apache-2.0 许可和适配署名。不创建或操作远端源仓库。
6. 对插件格式与代表性场景做有效验证：固定选项被动态化、单次调用小方法、应保留的共享校验、不可合并的事务边界，以及删除“全部”选项的行为变化。检验决策与边界，不以关键词匹配代替效果。

## 非目标

- 不改 `ai-image-gen` 业务代码；不安装整个上游技能包，不加入其分支、提交等流程规则。
- 不复制 ai-dev-protocol 的需求、spec、计划、提交、合并和交付流程；不加隐藏状态、额外公开 skill、无用目录或通用发布框架。
- 不将上游 JS/React 专属风格施加到 Java 或其他项目；不借简化删除功能。

- 业务 API、数据库和依赖：无。

## 实现与审查

先按 `skill-creator` 与 `plugin-creator` 格式在独立源码目录建立插件；将上游保留行为、消除无益抽象的思想改写为面向本项目的判断规则和 Java/Spring 示例，注明来源及许可。验证源码版本后导出可追溯快照，按仓库指南补齐安装入口和独立更新说明，避免声称现有 ai-dev-protocol 同步脚本维护新插件。以针对产物的格式检查、场景推演和范围/兼容性自检审查；复杂度允许时进行独立审查。

## 验证方式

- 运行 skill、plugin 和 marketplace 的适用验证器、`git diff --check` 及相关仓库测试。
- 用五个情境检查实际建议：识别不必要动态查询及多余抽象，保留共享校验和事务边界，把删除现有选项判为需求变化；复核普通代码审查请求能发现该 skill，审查模式不改代码、修改模式不越界。
- 记录验证覆盖的工作区内容和未覆盖的真实平台安装行为。

## 风险与范围变化

仓库目前主要维护 `ai-dev-protocol` 发布快照，现有同步/校验脚本不会自动覆盖新插件；只增加本插件所需的身份、来源和维护约束。新源码目录暂时没有远端，后续发布仍需单独授权。若发现需要新增或取消影响区域，先说明并更新 spec；新增远端仓库、推送或合回须另行授权。
