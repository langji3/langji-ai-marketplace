# 插件可靠性、接入与恢复执行 Spec

## 背景与目标
基于 2026-09-07 的两仓审查，完成用户已确认的三阶段、六单元执行方案：安全同步、可追溯发布和自动检查、完整安装、规则收敛与行为评测、Git 恢复、Apifox 失败恢复。

## 授权与分支
- 用户在当前对话明确回复“确认”，批准已列明的目标、范围、验证和从两仓 main 创建独立工作分支、实现、审查、提交。
- 两仓工作分支：codex/20260907-plugin-reliability；按当前宿主分支命名要求使用 codex/。
- 来源：ai-dev-protocol main 5b0522bf5f7ace9a394861fe064c4c1f29a86c67；marketplace main b4b3cb0bdd1119585443f2d600b3b77a6a3de098。
- 本文落成已确认的中文执行方案，不再重复索要相同范围的实施许可。
- 交付停留工作分支；合回 main、推送、发布、修改个人插件缓存和真实 Apifox 写入不在本次实施授权中。

## 范围与影响区域
1. marketplace scripts：保留 PowerShell 入口，由 Python 标准库实现 Git 提交导出、路径隔离、临时校验、失败恢复、同步互斥、版本索引更新和来源记录。
2. source scripts/tests：静态插件校验、完整资源包生成、可复现行为场景与记录校验；维护脚本中供安装后自检使用的 validator 随发布包交付。
3. 两仓 CI：静态检查与离线隔离测试，Windows 执行 PowerShell 入口，Python 检查跨平台执行。
4. source adapters/docs：完整资源包使用 vendor/ai-dev-protocol/，提供明确安装、升级、核验和卸载路径。保留单文件为摘要模式。
5. source skills/templates：单 Router 和 8 个 phase 保留；收敛重复规则，支持上下文明确授权，记录 spec 确认版本和验证提交，明确并发工作目录隔离、合回前目标变化及合后验证。
6. Apifox：分离摘要、清单、CLI 按需资源；增加逐项结果、未知结果回查、部分成功恢复和远端变化处理。
7. manifests/changelog/readme：兼容功能扩展版本 2.2.0，同步到 marketplace 的发布快照和版本字段。

## 非目标
不增加第二个 plugin、通用 marketplace 框架、MCP/hook、任务数据库或业务 API；不操作真实 Apifox 项目；不声称离线演练等于真实平台运行。

## 六单元顺序
安全同步与验证基础 -> 发布追溯/索引/CI -> 完整安装 -> Router/场景评测 -> Git 恢复 -> Apifox 恢复。
共用基础工具允许相邻单元一同实现，提交按可审查范围拆分。最后从源仓库提交导出快照并核验两仓一致性。

## 验证
- manifest/schema 必需字段、版本、唯一 Router、PHASE 无 frontmatter、资源链接、允许发布文件和内容摘要。
- 非法路径、源目标重合、源未提交变更、未追踪杂文件、损坏 manifest、复制/替换/元数据失败、重复同步、恢复与工作区保护。
- 全新离线目录生成和自检完整安装包。
- 约 15 个行为场景，断言实际操作/状态；记录工具版本、输入、产物、结果和未覆盖项，不使用措辞匹配冒充行为验证。
- Git 来源前进、spec 修改后恢复、独立工作目录与冲突；Apifox 部分成功、超时未知、授权后远端变化用模拟原始响应演练。
- 官方本地 plugin/skill validator、git diff --check、独立子代理审查。环境缺失的真实平台安装测试标记未验证。

## 风险与范围变化
跨文件替换不能保证突然断电时完全不可见；用保留旧快照、持久恢复记录和新同步阻断实现明确恢复，不将中断状态误报成功。
仅为同一范围补充脚本、测试、文档和发布清单无需重开授权；新增外部写入、改变硬门禁、扩大产品范围时单独说明并确认。
